# Append-only authority repair results

M006-S01 changes only resolution-authority reading. A disposable Git fixture first reproduced the original failure: after appending a later decision, the existing artifact check returned `drift: 00_brief/decisions.md` for the unchanged historical resolution hash. The initial focused unittest run failed on that assertion.

The repaired reader accepts the unchanged current file directly. For an appended file, it searches at most 256 same-path changes reachable from `HEAD`, with Git replacement objects disabled. It requires a blob whose normalized SHA-256 equals the recorded hash and requires the entire normalized original to be an exact prefix of current content. The reader returns those original bytes. Git calls have five-second per-call timeouts; both current and historical content are limited to 2 MiB. Missing files, altered old text, truncation, wrong hashes or paths, and absent reachable history fail closed. Ordinary event artifacts, outcome references, and evidence references retain exact-current-file checks.

`ledger.artifact_errors` and `_integrity.errors` use this reader only for `resolved` event authority. Coding prompt construction receives the complete original cited content and its original hash. If that makes the prompt too large, the existing support-artifact mechanism stores the complete original context and points the prompt to it. A later appended decision does not enter that historical resolution context. The historical search limit may reject a valid authority more than 256 same-path commits old; it does not silently accept a newer document.

Focused verification: the initial `python -B -m unittest discover -s tests -p test_authority_history.py -v` passed eight tests before clean-export verification showed that `/tests` is excluded from the candidate tree. Relocating the suite to `scripts/` fixed that missing-file failure. A subsequent clean-candidate run reached all eight tests but failed during fixture commits because its private `GIT_DIR`, `GIT_WORK_TREE`, index, and object selectors overrode fixture `git -C` paths. The test suite now reads the existing owner identity from the parent candidate first, then removes only repository selectors from its own process environment for the disposable fixture, restoring them at cleanup. A regression test demonstrates that poisoned selectors redirect Git before isolation and that the isolated fixture and authority reader use the fixture afterward. The maintained hermetic command invokes `python -B scripts/test_authority_history.py` directly; that entry point fails for an empty or skipped suite, and a missing file fails at process start. The focused command passed nine tests, and the parent repository HEAD and index byte hash were unchanged before and after. The architect runs the authoritative full verification after recording the coded candidate.
